# Interval timing: passive Link peer + relay-authoritative interval clock

How WAIL keeps intervalic audio beat-aligned across the WAN, given that Ableton Link shares only tempo and beat *phase* (mod quantum) within a session and shares nothing across separate LAN sessions (`Link.hpp:265-273`). This supersedes the previous model where each peer computed its interval index independently and a joining peer's beat was `ForceBeat`-snapped to the room owner.

## Decisions

- **WAIL is a passive local Link peer — no `ForceBeat`.** It never yanks the local session's transport to the room grid (the old behavior, disruptive to the local musician's DAW). Within-interval beat alignment comes for free from the local LAN's Link phase, asked at the interval quantum (see the index/phase split below).
- **The interval index is a relay-authoritative, room-shared logical clock** (NINJAM's server-metronome model). The relay server tracks tempo + interval config, owns the room interval index, and is the single clock reference every WAIL measures against. All WAILs agree on the index *by construction* (one authority), which also resolves the cross-WAN clock-domain problem — peers reference the one server clock instead of trying to reconcile N independent Link clocks (the reason the old clock-offset computation was dead and removed).
- **Index/phase split.** The shared room index supplies the interval *count* and the offset; local Link phase supplies the exact within-interval boundary. Every Link timing call on the audio path asks at quantum = **bars × quantum (BPI)**, not beats-per-bar: Link shares beat phase only mod the quantum asked for, so the bar lens pinned `beat mod 4` but left `beat mod BPI` — which bar starts the interval — per-peer arbitrary (audio landed bar-aligned but whole bars apart whenever Bars > 1). At the BPI lens the interval grid itself is session-shared, and quantum grids share a common origin, so interval boundaries stay bar-aligned and coincide with a DAW's interval-length launch quantization (ADR-0004). Each WAIL labels its own local interval boundaries with the agreed room index; the interval's worth of slack absorbs the RTT-scale skew between the server tick and a local boundary.
- **Configurable interval offset `D`, default 1.** Peer A's audio captured during room interval `N` is played by every other peer at *its* local boundary labeled `N + D`. The delay is enforced by the receiver's **hold-until-boundary scheduler** — pending intervals are held and released at the `N+D` boundary — not by network timing, so the offset is a fixed musical constant, jitter-proof as long as delivery beats the boundary. `D` is the reliability-vs-latency knob: raise it for slow/lossy links.
- **Late/incomplete at the playout boundary → play-partial + live-append, never silent.** If an interval is not fully delivered by its `N+D` boundary, publish what has arrived and splice late frames in as they land (the delay stays `D`), rather than slipping the whole interval to `N+D+1`. A fixed, predictable offset matters more to players than a rare brief gap. Every such event is logged at `warn` and counted as a per-direction/per-stream "interval incomplete" metric — distinct from capture-side LAN loss (Link Audio per-buffer `count`-sequence gaps) and decode failures, all surfaced in the metrics/dashboard (pillar 8).
- **Interval = beat window** (`bars × quantum` beats), WAIL works internally at 48 kHz (resample at the capture edge if a channel differs), and does **no clock recovery** — beats + tempo + sample rate are the only timing Link Audio provides (`LinkAudio.hpp:309-337`), so a beat window is the only well-founded interval definition. Any residual audio-clock drift is absorbed by the endpoints' own Link Audio resampling.

## Consequences

- There is no wall-clock-global interval start across sites — each LAN's boundaries sit at its own Link phase — but interval-*relative* placement is pinned: frame offsets transfer exact positions within the interval, so every listener hears every peer aligned to their own interval grid (the NINJAM guarantee, at interval rather than bar granularity). A future feature needing a room-wide count-in or aligned multi-site recording would re-introduce an optional grid anchor.
- The relay server gains a small, contained responsibility (own the room interval clock) — a conscious softening of the dumb-broadcast-relay stance (CONTEXT.md pillar 5). It is a narrow clock role, not general logic creep, and it simplifies every client.
- The WAIF `interval_index` field now carries the *room* index, so the per-peer `rewrite_waif_interval_index` remap is no longer needed.
