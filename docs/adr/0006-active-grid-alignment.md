# Active grid alignment: entry snap + gated grid slew

Status: accepted (amends ADR-0003 decision 1; implementation follows)

Under ADR-0003, WAIL is a purely passive Link peer: the relay owns the room interval index, and each client maps its local grid to the room grid with a constant label offset. That keeps indices consistent but never physically aligns the grids — the offset is fixed from an anchor sampled at send time against a local index sampled at receipt time, so two peers holding the same anchor can disagree by a whole interval, persistently, re-rolled on every anchor (the labeler hazard, pinned in `internal/interval/labeler_hazard_test.go`). Even when the offset lands correctly, heard content sits at an arbitrary phase relationship (up to half an interval) forever, and crystal drift (~3 ms/min) degrades it further over long jams.

**Decision: WAIL actively aligns its local interval grid to the relay's room grid, under two narrow rules.** The relay room clock remains the single fixed reference — peers never measure or chase each other, so alignment is transitive (`|δ_A − δ_B| ≤ |δ_A| + |δ_B|`) with no peer-to-peer feedback path and nothing to oscillate.

1. **Entry conformance** (join and rejoin, one unified rule): adopt the room tempo, measure the alignment error δ — the phase distance between the local grid and the room grid, from the anchor's `server_now_micros` (already on the wire, previously discarded) plus a relay RTT estimate, against the local `TimeAtBeat`/`BeatAtTime` grid — and `ForceBeatAtTime` onto the room grid **only if |δ| exceeds the perceptual threshold (~25 ms)**. First joins and app restarts measure an arbitrary δ and snap; mid-blip reconnects (local session ran continuously through the outage) measure δ ≈ 0 and no-op; a second WAIL on an already-aligned LAN no-ops. The measurement, not the event type, forks the behavior — there is no `isReconnect` branch, and re-running entry is idempotent.
2. **Gated grid slew** (steady state): when |δ| crosses the threshold mid-session, nudge local tempo by a bounded amount (≤0.3%) until δ closes, then restore the exact room tempo. Gates: a 3 s wall-clock suppression after any tempo change (local user's hand or remote adoption — deliberately longer than the 150 ms echo guard, so the loop never chases a human mid-gesture), a 5 s settling window after an entry snap, and **never a `ForceBeat` outside entry** — snaps belong to transition moments, slew to steady state, and the two never substitute. Both gate durations are heuristics (see tradeoffs.md). The slew's tempo baseline is the anchor's authoritative room tempo, not the client's last broadcast (they can differ by the adoption threshold).

δ is logged per interval and surfaced as an alignment state (aligned / aligning / drifted) in the UI and health snapshot. Both rules are default-on; no opt-in flags (pre-users, flags would only be unexercised code paths).

This amends ADR-0003 decision 1 ("passive peer — no `ForceBeat`") and CONTEXT.md pillar 4 with exactly these two carve-outs; the gating rule above is the amendment's literal wording. Everything else in ADR-0003 stands: the relay-authoritative index, the index/phase split at the BPI lens, hold-until-N+D, live-append.

## Considered options (rejected)

- **Tunnel Link's sync protocol across the WAN.** Link's timeline measurement is RTT-compensated and assumes LAN latency; over WAN jitter it imports jitter directly into everyone's tempo/phase. Discovery payloads embed unroutable LAN endpoints, so "raw" tunneling requires an application-layer gateway anyway. Violates pillar 5's spirit.
- **Ghost peers** (WAIL synthesizes one local Link peer per remote musician, speaking Link's wire protocol on the LAN multicast). Link's convergence assumes every peer is LAN-close and equally authoritative; a multi-LAN convergence loop with seconds of delay in it can oscillate. Also requires implementing Link's wire protocol, and Link has no membership semantics for two established sessions meeting (impossible on a LAN, routine here).
- **Emergent WAN consensus** (no authority; peers converge on a merged timeline). Same delayed-consensus oscillation; stabilizing it means de-tuning until it no longer resembles Link's algorithm.
- **Label-only alignment** (fix the labeler hazard via boundary-quantized/RTT-compensated alignment without touching grids). Makes indices consistent but leaves heard content at an arbitrary phase relationship; does nothing about drift.
- **PLL labeler** (baked offset + hysteresis re-lock, validated in `internal/interval/anchorsim_pll_test.go` over the two-grid harness from #420): keep the label-only model, but re-lock the offset after N consecutive disagreeing boundaries so a local-grid jump heals in ≤3 boundaries instead of persisting forever. Rejected as the primary direction: it manages *labels* while the grids stay physically misaligned forever — heard content sits up to half an interval (seconds) off phase permanently, and every correction is an interval-quantized jump in what receivers play, versus the grid slew's smooth ≤0.3% tempo corrections. Grid alignment removes the misalignment instead of administering it. **Retained as the pre-validated fallback:** if field evidence contradicts this ADR (snap/slew misbehaving on real rigs), the simulation-validated PLL labeler is the documented alternative, and the anchorsim harness stays as regression cover for the label-only fallback path.
- **Do nothing about drift** (snap only). ~180 ms/hour at 50 ppm; audible over long static-tempo jams.

## Consequences

- The labeler hazard evaporates for snapped peers: a snapped grid *is* the room grid (to within RTT/2), so the offset is known by construction. `RoomLabeler` survives as the fallback for pre-anchor / headless / Link-disabled states.
- Pairwise heard skew between two peers is bounded by 2×threshold plus RTT/2 estimation error (~50 ms worst-case transient, typically much less), vs. arbitrary and permanent today. The design target is ~25 ms-class agreement — right for intervalic playout, and the honest bound given WAN time transfer.
- A mid-jam tempo change re-anchors the room clock (beat-continuous via the transition pin) and peers adopt it beat-continuously; δ persists approximately and the slew mops up any discrepancy. The tempo-changer's grid does **not** become the phase reference — the relay owns room phase even when a peer owns the tempo change.
- Requires: a relay-RTT/offset estimate (upgrading Ping/Pong to carry server time), δ measurement in `internal/interval`, the snap in the session join path, and the slew loop in the Link bridge. The anchor wire format already carries everything needed (`server_now_micros`); the implementation adds `next_boundary_micros` for exact boundary times.
- **Supersedes the PLL-labeler proposal** from #420's field hunt (see Considered options): grid alignment is the primary direction, decided before wide field evidence, on the strength of the design argument (physical alignment beats label administration). The anchorsim two-grid harness and PLL simulation remain in the tree as the validated fallback and as regression cover for the label-only path.
- Local musicians on a joining peer's LAN feel the snap if their transport is playing. Accepted: joining is a user-initiated transition moment and the snap only fires when genuinely misaligned; established room members are never snapped.
